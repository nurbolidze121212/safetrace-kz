# Архитектура SafeTrace KZ 2.3.0

Браузер и вычисления разделены, но поставляются одним локальным приложением. FastAPI отдаёт собранный React и `/api`. OCR, QR, правила, обращения к разрешённым адресам, SQLite и экспорт выполняются на компьютере с сервером. В браузере нет весов моделей и серверных ключей.

## Поток данных

```text
Текст / URL / изображение
  -> проверка формата и размеров -> оригинал и SHA-256
  -> очередь до 8 задач, 1 исполнитель
  -> OCR / QR -> фрагменты и адреса
  -> спорный OCR? остановка + явная сверка
  -> ограниченный обход разрешённых узлов
  -> контекст и привязка призыва к ветви
  -> индекс -> граф -> SQLite
  -> просмотр источников -> решение -> ZIP

Сохранённый случай -> GET link-audit
  -> пассивный разбор URL и текста без DNS/HTTP
  -> отдельный JSON с признаками и невыполненными проверками
```

## Компоненты

| Модуль | Ответственность |
|---|---|
| `backend/app.py`, `schemas.py`, `limits.py` | API, валидация, ограничения запросов |
| `pipeline.py` | Очередь, этапы, отмена и история |
| `ocr.py`, `ocr_urls.py`, `qr.py` | Чтение изображения и сверка адресов |
| `links.py` | Сетевой транспорт, наблюдения и связи |
| `analysis.py`, `attribution.py` | Признаки, контекст, принадлежность призыва ветви |
| `graph.py`, `storage.py` | Граф, SQLite, кэш и решения |
| `exports.py`, `report_html.py` | Проверка оригиналов и досье |
| `link_audit.py` | Новый пассивный разбор других признаков |
| `frontend/src/components/` | Ввод, показ, источники и решение |

## Границы доверия

Сообщения, изображения, HTML и ответы модели — данные, не команды. Облачные claims проходят схему и сверку точной цитаты. Оригинал хранится отдельно от нормализованного текста. Недоступная страница или сомнительный URL не превращается в безопасный результат.

API проверяет Host и Origin. Управляемый сервер слушает только `127.0.0.1`; блокировка папки данных не позволяет двум процессам использовать одну базу. Это однопользовательская рабочая станция, а не многопользовательская система с авторизацией.

Сетевой обход допускает только HTTP/HTTPS, порты 80/443, точный allowlist. Запрещены учётные данные в URL, частные и специальные IP; DNS-адрес проверяется и фиксируется при подключении. TLS проверяется. Пределы: 12 запросов, глубина 4, ответ до 256 KiB; действуют ограничения времени. JavaScript не исполняется. Каждый переход проходит ограничения заново.

Пассивный аудит не обходит сетевые запреты: IP, `.exe` или подозрительный URL разбираются как строки. Справочник доменов локальный, источник и срок пересмотра видны в отчёте. [Спецификация](EXTENDED_ANALYSIS.md).

## Хранение и версии

`data/safetrace.sqlite3` содержит случаи, историю, решения и кэш; `data/originals` — изображения. Эти папки не публикуются статическим сервером и не включаются в Git. API выдаёт изображение по ограниченному идентификатору.

Версия приложения 2.3.0 сохраняет rules-4.0 / pipeline-2.2.1. Дополнительный отчёт имеет собственную схему `link-audit-1.0`, дату генерации и analysis_id исходного случая. Он вычисляется при чтении, старый случай не переписывает. Для фиксации скачивается отдельный JSON; основной ZIP пока не включает его автоматически.

Локальная схема сохраняет оригиналы у пользователя и работает после установки без облака. Компромисс — зависимость от включённого ПК, CPU и локальных моделей. SQLite и один исполнитель подходят для показа одним аналитиком; многопользовательская производительность не доказана.

## Перенос и телефон

Копирование только `frontend/dist` даёт оболочку без анализа. Другому компьютеру нужны Python-сервер, зависимости и OCR-модели. Он может работать с новой базой или восстановленной копией. [Инструкция переноса](INSTALL_AND_TRANSFER.md).

На телефоне `127.0.0.1` означает сам телефон. Замена host на `0.0.0.0` не добавляет авторизацию и противоречит текущей проверке Host/Origin. План подключения: одноразовый QR, ограниченная сессия, HTTPS, право загрузить материал без чтения всей базы, квоты и отзыв сессии. Это ещё не реализовано. Публичный frontend дополнительно потребует конкретного API-origin и CORS-политики; сервер должен быть доступен телефону. Рабочая база наружу не открывалась.
