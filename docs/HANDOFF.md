## Комплект для другого каталога или компьютера

Локальный выпуск сохраняется в `deliverables/releases/` и состоит из архива исходников с собранным интерфейсом, отдельного архива демонстрационных данных и файла с SHA-256. Внутри исходников есть `PACKAGE_MANIFEST.json` с коммитом и хешами каждого включенного файла.

Исходники включают код, тесты, синтетические наборы, сохраненные оценки, PPTX и лицензионные уведомления интерфейса. В них нет `.env`, ключей, базы, `.git`, Python-окружения, `node_modules` и весов OCR. Это не автономный исполняемый файл: на новом компьютере нужна первоначальная установка Python-пакетов, моделей и Node-зависимостей.

1. Распакуйте исходники в новую папку с ASCII-путем, например `C:\SafeTrace-KZ`. Пробелы допустимы, кириллица в полном пути моделей не поддерживается этой Windows-сборкой OCR.
2. Установите Python 3.12 x64 и Node.js 22.12+ / 24 LTS. Интернет нужен для первоначальной установки. Откройте PowerShell в папке с README.md.
3. Выполните `powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1`. Для явного выбора Python: `-PythonPath 'C:\Path\Python312\python.exe'`.
4. Если нужны подготовленные случаи и история, восстановите отдельный архив данных **до первого запуска**. Если он лежит рядом с папкой проекта:

```powershell
.\.venv\Scripts\python.exe scripts\backup_data.py verify ..\SafeTrace-KZ-v3-demo-data.zip
.\.venv\Scripts\python.exe scripts\backup_data.py restore ..\SafeTrace-KZ-v3-demo-data.zip --to data
.\.venv\Scripts\python.exe scripts\preflight.py
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Offline -Background
```

Существующая папка `data` не заменяется. Если вы уже запускали приложение, используйте [восстановление в отдельную папку](BACKUP.md). Без восстановления данных приложение начинает с пустой очереди и доступных демонстрационных карточек. Ссылки на подготовленные случаи из DEMO_V3.md появятся после восстановления базы.

После установки локальный анализ, синтетические переходы и экспорт работают без сети и Gemini. При повреждении файлов OCR используйте [восстановление моделей](MODEL_RECOVERY.md). На другом компьютере весь сценарий нужно проверить до выступления: на этом стенде проверены чистое Python-окружение и перенос в другую папку, но отдельное физическое устройство не испытывалось.

## Какие результаты можно заявлять

Новый авторский синтетический тест: 80 случаев, 32 изображения; TP32 / FP1 / TN39 / FN8. Precision 96,97%, recall 80%, FPR 2,5%, достаточные данные в 69 из 80 случаев. Семь положительных отказов включены в пропуски. Это результаты синтетического набора с широкой неопределенностью, без независимых разметчиков; качество на реальных соцсетях неизвестно.

Индекс задает приоритет проверки. Система не устанавливает владельца и не выносит юридический вердикт. Живой Gemini, Linux и GPU не проверены. Подробные границы и ошибки сохранены рядом с метриками, а текущие проверки — в [ACCEPTANCE_V3](../reports/ACCEPTANCE_V3.md).
