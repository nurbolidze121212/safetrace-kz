# Управление локальным сервером

Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Offline -Background
.\.venv\Scripts\python.exe scripts\preflight.py --server
powershell -ExecutionPolicy Bypass -File .\scripts\stop.ps1
```

Запуск в фоне сообщает готовность после успешного `/api/health`. Для другого порта добавьте `-Port 8767` к обеим командам; проверке установки — `--port 8767`. Журналы разделены по порту: `logs/server-8765.out.log` и `logs/server-8765.err.log`. `logs/server-8765.json` содержит PID фактического Python-процесса и случайный идентификатор запуска.

Без `-Background` сервер работает в текущем терминале и завершается Ctrl+C. Настройки `-Offline` и кодировки, временно заданные скриптом, после его завершения не остаются в вызывающем PowerShell.

## Один процесс на папку данных

`start.ps1` использует `scripts/run_server.py`. До импорта приложения и восстановления прерванных задач он получает блокировку ОС на `data/.safetrace.lock` и резервирует порт только на `127.0.0.1`. Второй управляемый экземпляр с той же папкой данных отклоняется, даже если выбран другой порт. Файл блокировки может оставаться после закрытия; важна блокировка работающего процесса, а не наличие файла. После аварийного завершения ОС освобождает её автоматически.

Независимые папки данных могут работать на разных портах. Например, [проверка резервной копии](BACKUP.md) использует `SAFETRACE_DATA_DIR` в отдельном PowerShell. Путь нормализуется перед блокировкой.

Для обычной работы используйте `start.ps1`. Прямой запуск `uvicorn backend.app:app` обходит эту защиту; несколько таких процессов или несколько workers на одной базе не поддерживаются. Правила анализа и зафиксированное ядро v3 не изменялись: защита добавлена на уровне локального запуска.

## Остановка

`stop.ps1` сверяет проект, PID, имя Python-процесса, путь запуска, случайный идентификатор в командной строке и владельца порта. Устаревшая запись с чужим PID не даёт права остановить процесс. Если API сообщает ожидающий или выполняемый анализ, команда отказывает: дождитесь результата либо отмените задачу в интерфейсе и повторите команду. Это проверка очереди непосредственно перед остановкой; во время остановки не отправляйте новые задания.

Фоновый процесс останавливается средствами Windows. Сохранённые данные остаются; для планового завершения из исходного терминала доступен Ctrl+C. Если сервер запущен старым способом и управляющей записи нет, завершите его в исходном терминале. Скрипт не ищет и не останавливает произвольный процесс по одному номеру порта.

При занятом порту, занятой папке данных или сбое запуска возвращается ошибка. Если за 20 секунд готовность не подтверждена, прочитайте журнал соответствующего порта; сообщение не утверждает, что сервер готов.

## Проверка на этом компьютере

На изолированной копии прежний запуск действительно позволял два сервера на одной базе; запись ручного решения через второй была видна первому. После изменения второй управляемый процесс отклонён. Проверены освобождение блокировки после обычного и аварийного завершения, отдельные папки, занятый порт до запуска приложения, неверный идентификатор процесса и отказ остановки при контролируемом статусе `running` в очереди.

Основной стенд переведён на новый запуск: все 21 случая, семь решений и семь оригиналов совпали до и после, контрольный ZIP прошёл проверку пяти файлов.
