# Контейнер CPU: готовый образ v3.0

Нужны Git и Docker Engine / Docker Desktop с Compose. Из папки проекта:

```sh
docker compose up -d
```

Compose скачивает опубликованный `ghcr.io/nurbolidze121212/safetrace-kz:3.0.0` с уже включёнными OCR-моделями, а также Redis. Первая загрузка требует интернета и зависит от размера образа; во время запуска модели не скачиваются. Откройте [локальное приложение](http://127.0.0.1:8765). Для сборки из исходников используйте `docker compose -f compose.yaml -f compose.build.yaml up --build -d`.

Образ использует Linux amd64 / Python 3.12 / CPU. Compose запускает API, Redis и отдельный воркер; `docker compose up -d --scale worker=4` задаёт четыре процесса. SQLite остаётся единым узлом записи, это не распределённое хранилище. Compose публикует API только на `127.0.0.1` компьютера; Redis наружу не опубликован. На ARM Mac используется эмуляция amd64; производительность на физическом Mac не измерена. Контейнер не открывает рабочую папку проекта или личную базу: данные находятся в именованных томах Compose.

```sh
docker compose logs -f
docker compose stop
docker compose start
```

Для остановки и удаления контейнера без удаления данных: `docker compose down`. Опция `-v` удаляет том с данными — не используйте её для рабочей базы.

Внешние страницы по умолчанию отключены (`SAFETRACE_OFFLINE=1`). Для согласованного живого исследования владелец должен отдельно настроить режим и точный список `SAFETRACE_ALLOWED_HOSTS`. Включение сети не подтверждает безопасность или законность произвольного сайта.

GitHub Actions строит контейнер, запускает его, создаёт новый текстовый случай, отправляет изображение в настоящий OCR и проверяет ZIP. [Завершённый Linux-запуск с Redis, реальным OCR и 1–4 воркерами](https://github.com/nurbolidze121212/safetrace-kz/actions/runs/40206555664); [числа и условия замера](SCALE_BENCHMARK_V5.md). Статус проверки текущего образа смотрите в [Actions](https://github.com/nurbolidze121212/safetrace-kz/actions/workflows/ci.yml).
