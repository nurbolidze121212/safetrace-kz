# SafeTrace KZ: что показывать на демонстрации

Выбран трек 2 «Скрытая игра»: поиск признаков скрытого продвижения онлайн-казино. SafeTrace помогает аналитику разобрать материал, восстановить доступный рекламный маршрут и проверить основания. Программа не проверяет все виды мошенничества и не определяет, безопасна ли любая ссылка.

Фраза для первого знакомства:

> «Приходит сообщение с обещанием бонуса, но без слова “казино”. Я добавляю его в SafeTrace. Программа показывает, куда ведёт рекламный маршрут, какие игровые признаки найдены и на каких сохранённых источниках основан вывод. Решение остаётся за аналитиком».

## Показ на ноутбуке с сообщением с телефона

1. Открыть [приложение](http://127.0.0.1:8765/#queue). Нажать «Проверить сообщение».
2. Вставить текст целиком, отдельную ссылку или загрузить сохранённый скриншот PNG/JPEG/WebP. На компьютере поддерживается вставка изображения из буфера. WhatsApp автоматически не читается; материал добавляется вручную.
3. Для своего материала оставить локальный режим. Для собственных адресов `.test` раскрыть «Название, источник и настройки» и выбрать «Синтетический стенд».
4. После отправки автоматически откроется «Режим показа»: оригинал, индекс с причинами и карта находятся рядом. Нажать причину или шаг карты, чтобы открыть сохранённый источник. Для подробностей есть «Оригинал и распознанный текст», «Подробный граф» и «Рабочий режим».
5. Сравнить с предупреждением на ту же тему: наличие слов «казино» и «бонус» само по себе не означает продвижение.
6. Сохранить решение аналитика и скачать ZIP. Внутри — HTML, JSON, оригиналы и manifest с SHA-256.

Удобные случаи, созданные и проверенные браузером 22.10.2026:

- [Фото без добавленного текста: индекс 80 и карта](http://127.0.0.1:8765/#case/f5f469d29f644ad59389cce99cad96ce?view=presentation). Это основной пример для показа. Исходное изображение: `examples/import/picture.png`; для нового прохода выбрать синтетический стенд. Реальный OCR и анализ заняли 12,4 с в этом запуске.
- [Скрытый маршрут: индекс 80, три наблюдения](http://127.0.0.1:8765/#case/1c88aea6e3d04685895a8799c0eeae26).
- [Предупреждение: индекс 0](http://127.0.0.1:8765/#case/452a2f7c90ce4f5795867ff775a6e8c4).
- [Ошибка одной буквы OCR: требуется сверка](http://127.0.0.1:8765/#case/893ba041645e42d88d12d6f3db6e562d).
- [Недоступная ссылка: недостаточно данных](http://127.0.0.1:8765/#case/737af2952ea24335b0548249de67cbd2).

Это демонстрационные и технические примеры, не новая независимая оценка качества. В предупреждении сохранено техническое решение с явной пометкой о происхождении.

В существующем случае нажать «Режим показа» сверху. Если материалов несколько, выбрать нужный: индекс, основания и маршрут относятся к нему. Стрелки различают HTTP-переход и ссылку на странице; разрыв маршрута остаётся видимым. Экспорт доступен прямо из режима показа.

Результаты проверок и оставшиеся работы: [отчёт итерации](../reports/MESSAGE_DEMO.md). Ночное продолжение настроено на 00:00, 02:00, 04:00 и 06:00 по Кызылорде; нужен работающий компьютер и доступный Codex. Задание: [NIGHT_IMPROVEMENT.md](../NIGHT_IMPROVEMENT.md).

## Текст для нового прохода

В режиме синтетического стенда:

```text
Синтетический пример для демонстрации. Забирай бонус по ссылке: https://go.safetrace.test/r/q7
```

Контрпример:

```text
Предупреждение: не переходите по рекламе казино и не вносите депозит. Обещание бонуса по ссылке https://go.safetrace.test/r/q7 — пример опасного предложения. Синтетический материал для обучения.
```

Эти адреса — собственный безопасный стенд. Они не открывают реальные казино и не изображаются как результаты исследования действующих сайтов.

## Если видна пауза или ошибка

- «Материал в очереди»: ждёт свободный обработчик; не отправлять повторно.
- «Читаем текст и ссылки»: OCR выполняется; процент изменяется между этапами. В новом холодном проходе этой итерации обработка одного изображения заняла 18,5 секунды. Это отдельный замер, не обещание времени для каждого файла.
- «Адрес распознан неоднозначно»: сверить с оригиналом. Адрес не исправляется и не открывается молча.
- «Часть маршрута недоступна»: открыть причину остановки. В текущем офлайн-режиме внешние страницы не запрашиваются.
- «Весомых признаков не обнаружено»: низкий приоритет по этому треку; не сертификат безопасности ссылки.

## Телефон и подключение

Мобильная вёрстка проверена в браузере при 360×800 и 390×844. Физический телефон, его клавиатура и системный выбор фото в этой итерации не проверялись.

Адрес `127.0.0.1` относится к тому устройству, на котором его открыли. На телефоне он не подключает к ноутбуку. Текущий сервер принимает только локальные подключения; публичного адреса и подключения телефона по Wi-Fi пока нет. Для текущего показа скриншот или текст нужно передать на ноутбук обычным способом и добавить в приложение. Сам показ внутри браузера телефона потребует отдельного ограниченного доступа с проверкой на устройстве.

## Запуск при закрытом сервере

В PowerShell из папки проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Offline -Background
```

Открыть http://127.0.0.1:8765. Если порт уже занят работающим SafeTrace, второй экземпляр не нужен. Для остановки: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop.ps1 -Port 8765`.

## Что улучшать дальше по существу

1. Повысить полноту точного чтения URL на изображениях, сохранив остановку сомнительных адресов. Новые dev-примеры, затем новый замороженный тест.
2. Улучшить отрицания и связь рекламного призыва с назначением в русском и казахском тексте; не подгонять правила под final-v4.
3. Проверить разрешённые реальные материалы и маршруты с независимой разметкой. Синтетический тест не подтверждает качество на всех соцсетях.
4. Подготовить ограниченный режим подключения телефона и проверить его на реальном устройстве.

Сильная сторона для защиты — прослеживаемый маршрут и проверяемые основания, включая честную остановку при нехватке данных. Первое место этими изменениями не гарантируется. Итоговые метрики v4 остаются прежними: precision 93,75%, recall 75%, FPR 5% на 80 авторских синтетических случаях; цели precision 95% и recall 80% ещё не достигнуты.
