# Резервная копия и восстановление

`scripts/backup_data.py` сохраняет согласованный снимок SQLite и все изображения, на которые ссылаются текущие материалы или история анализа. В базе остаются тексты, наблюдения, графовые основания, ручные решения и кэш. Копирование SQLite выполняется через backup API: учитываются подтвержденные записи WAL, незавершенная транзакция другого соединения не попадает в снимок.

## Создать и проверить

В корне проекта, даже при работающем сервере:

```powershell
.\.venv\Scripts\python.exe scripts\backup_data.py create --output data\backups\before-demo.zip
.\.venv\Scripts\python.exe scripts\backup_data.py verify data\backups\before-demo.zip
```

Для повторной копии выберите новое имя: существующий ZIP не перезаписывается. Путь данных берется из `SAFETRACE_DATA_DIR`, затем `.env`, затем `data/`; явный `--data-dir` имеет приоритет. Архив содержит снимок на момент резервирования. Изменения, внесенные после снимка, попадут в следующую копию.

Проверяются CRC ZIP, SHA-256 и размеры файлов, `quick_check` SQLite, число случаев и решений, хеши оригиналов в базе и наличие изображений из истории. Поврежденный или отсутствующий оригинал прерывает создание. Код выхода 0 означает успех, 1 — ошибку. Если в снимке есть ожидающие или выполняемые задачи, инструмент сообщает их число; приложение при запуске восстановленной копии пометит их прерванными и позволит повторить анализ.

## Восстановить в отдельную папку

```powershell
.\.venv\Scripts\python.exe scripts\backup_data.py restore data\backups\before-demo.zip --to data-restored
```

Папка `data-restored` должна отсутствовать. Сначала проверяется весь архив во временной папке, затем копируются проверенные данные. Существующая база или папка не заменяются. Если ошибка диска возникла уже при копировании, не запускайте незавершенную папку: повторите восстановление в новую. `backup-manifest.json` записывается последним после успешного копирования.

В новом PowerShell можно проверить восстановленную копию на другом свободном порту:

```powershell
cd C:\Users\nurbo\Desktop\vvv\safetrace-kz
$env:SAFETRACE_DATA_DIR = (Resolve-Path -LiteralPath '.\data-restored').Path
.\.venv\Scripts\python.exe scripts\preflight.py
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Offline -Port 8767
```

Откройте `http://127.0.0.1:8767`. Завершите тест Ctrl+C и закройте этот PowerShell, чтобы временный путь не использовался для дальнейших запусков. Основная копия на порту 8765 остается отдельной.

Архив данных не включает программу, Python-зависимости, модели OCR, `.env`, журналы и загруженные изображения, еще не связанные ни с одним случаем. Для другого компьютера сначала установите ту же версию проекта по README, затем восстановите данные. ZIP хранит содержимое случаев без шифрования; SHA-256 проверяет целостность, но не удостоверяет автора архива. Технические пределы инструмента: база до 512 MiB, одно изображение до 8 MiB, распакованный комплект до 1 GiB и 10000 файлов.

## Проверено на этом стенде

`data/backups/full-v3-20261021-0550.zip` восстановлен в `tmp/restore-v3-0550` и запущен отдельным сервером. Совпали очередь и полные API-документы всех 21 случая, семь ручных решений и семь оригиналов. Для всех 21 случая повторно проверены ZIP и хеши manifest. Браузер загрузил исходное изображение 1040×610, OCR и QR из восстановленной копии. Основная очередь не менялась; временный сервер остановлен.
