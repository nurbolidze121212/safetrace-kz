# Дополнительные проверки внутри случая: смысл результатов и API

Основная задача SafeTrace KZ — выявление скрытого продвижения азартных игр, трек 2 «Скрытая игра». Этот документ описывает вспомогательный анализ тех же сообщений, ссылок и скриншотов: имитацию имени, запросы секретов и признаки потенциальной загрузки программ. В 2.3.0 реализован ограниченный пассивный модуль. Его выводы и будущие репутационные интеграции дополняют разбор случая; они не заменяют основной трек и не доказывают связь материала с казино.

## Независимые вопросы

| Вопрос | Требуемые основания | Сейчас |
|---|---|---|
| Есть ли продвижение азартных игр? | Призыв, контекст, игровая страница и связь с ней | rules-4.0, сохранённые источники |
| Это домен известного бренда? | Датированный доверенный справочник, точная граница имени | Один пример Apple |
| Кто владелец сайта? | Независимая связь организации и домена | Не установлен |
| Есть ли действующая лицензия? | Реестр, юрисдикция, организация, срок и вид деятельности | Не проверяется автоматически |
| URL известен как фишинг/вредоносный? | Свежий ответ репутационного источника с scope | Не подключено |
| Страница собирает пароль? | Содержимое формы, получатель, контекст, изолированное наблюдение | Только узкие текстовые признаки |
| Файл содержит вирус? | Содержимое, хеш, движок/песочница и условия анализа | Не выполняется |

Лицензия организации не доказывает принадлежность домена. Логотип не доказывает лицензию. Отсутствие записи в одном каталоге не доказывает обман. «Реальное казино» не означает «легальный и безопасный ресурс».

## Что выполняет `link-audit-1.0.1`

Разбираются введённые адреса, ссылки из текста, принятые/уточнённые OCR-адреса, URL из QR и сохранённые наблюдения. Сомнительные OCR-адреса учитываются отдельно, без молчаливой замены. Лимит — 100 уникальных URL; превышение отражается в coverage.

Признаки: HTTP, IP вместо имени, punycode/Unicode, часть перед `@`, расширение потенциально исполняемого файла, встраивание известного домена в чужое имя. `apple.com.claim.example` не является поддоменом `apple.com`; `support.apple.com` является. Unicode показывается рядом с ASCII; сам punycode не доказывает фишинг. По расширению `.exe` нельзя установить наличие вируса.

Текстовый сигнал требует обещания приза и просьбы отправить пароль, SMS-код или CVV **в одном источнике**. Признаки разных материалов не суммируются. Некоторые предупреждения, новости и учебные контексты исключаются. Это узкие шаблоны RU/KK; сложные отрицания, формы и новые формулировки могут быть пропущены.

В патче 1.0.1 одинаковый признак объединяет существующие evidence IDs всех самостоятельно подходящих источников; повтор не создаёт дополнительный балл. Порядок материалов не должен скрывать доказательства. [Проверка исправления](../reports/NIGHT_EVIDENCE_2026_10_23.md).

Каждый признак содержит код, описание, конкретную строку и доступные evidence IDs. Два найденных текстовых фрагмента разделены `[…]`, а не выданы за одну непрерывную цитату. Подтверждения произошедшей кражи данных такой сигнал не даёт.

`fixtures/brand-reference.json` содержит только Apple, [официальный источник](https://www.apple.com/legal/privacy/en-ww/), дату сверки 22.10.2026 и дату пересмотра. Это внутренний срок обновления справочника, не срок действия домена. После него совпадение помечается как требующее обновления. Домены казино и реестр лицензий в справочник не включены.

## API и экспорт

`GET /api/cases/{case_id}/link-audit` возвращает JSON; неизвестный случай — 404. `?download=true` скачивает отчёт. Старый случай не меняется. DNS, HTTP, облачная модель, JavaScript и файлы не вызываются.

Основные поля: `schema`, `case_id`, `analysis_id`, `source_analyzed_at`, `generated_at`, `mode`, `status`, `probability: null`, `network_requests: 0`, `urls`, `findings`, `checks`, `coverage`, `held_ocr_urls`, `limitations`.

Статусы: `source_incomplete` для незавершённого/ошибочного запуска; `needs_review` при выбранных признаках; иначе `no_selected_indicators`. Последний **не означает safe**. `observed_urls` считает сохранённые HTTP-ответы без остановки, а не безопасные страницы.

Рабочая вкладка — «Другие угрозы»; в режиме показа есть ссылка под картой. JSON скачивается отдельно от основного ZIP. При повторном запросе дата генерации меняется. Общий антифишинговый процент не вычисляется.

## Источники для следующего этапа

Сверено по первичной документации 22.10.2026. Это исследованные кандидаты, **не действующие интеграции**.

| Источник | Применение и ограничения |
|---|---|
| [Google Safe Browsing](https://developers.google.com/safe-browsing), [v5 urls.search](https://developers.google.com/safe-browsing/reference/rest/v5/urls/search) | Известные угрозы; ответ содержит типы и срок кэша. Пустой ответ не удостоверяет безопасность. Safe Browsing предназначен для некоммерческого использования; Google отдельно указывает Web Risk для коммерческого. |
| [VirusTotal URL report](https://docs.virustotal.com/reference/url-info) | Чтение существующего URL-отчёта по ID, нужен ключ. Количество движков не является вероятностью, важна давность. |
| [VirusTotal Private Scanning](https://docs.virustotal.com/docs/private-scanning) | Отдельная платная услуга с отдельными правилами. Обычная отправка не становится приватной автоматически. Ничего не подключалось и не оплачивалось. |
| [URLhaus Community API](https://urlhaus.abuse.ch/api/) | Адреса распространения malware, нужен Auth-Key. По политике URLhaus фишинг не является его целевой категорией. |
| [Реестр лицензий букмекерских контор РК](https://www.gov.kz/memleket/entities/tsm/documents/details/1007126?lang=ru) | Официальный источник для конкретного вида деятельности. Не полный каталог интернет-казино и не доказательство связи домена с организацией. |

Контракт адаптера: источник, время, точный scope URL/domain/hash, свежесть, статус `matched/no_match/unavailable/not_configured`, кэш/квоты, обработка 429 и отказов. Перед внешней отправкой интерфейс должен назвать получателя и данные. Частные ссылки и секретные query-токены не должны молча уходить в публичный сканер. Ключ на сервере не заменяет согласие на передачу материала.

## Условия обоснованного процента

Нужны отдельные классы продвижения, фишинга, вредоносной загрузки и имитации бренда: классы могут пересекаться. Разделить домены/кампании/время между разработкой, калибровкой и финальным тестом; зафиксировать протокол заранее. Измерить precision/recall/FPR, покрытие, интервалы, Brier score/калибровочную кривую, ошибки по языку и типу ввода. До этого показываются признаки и индекс ручной проверки, а не «100%».
