# Данные и воспроизведение synthetic-v4

Новый набор создан после замораживания ядра 22 октября 2026 года в 01:37:49 Asia/Qyzylorda. Время генерации: 01:41:52. Корпус авторский синтетический; разработчик правил также написал тексты и разметку. Это не независимая экспертная проверка.

## Состав

80 случаев: 40 положительных и 40 отрицательных. 32 случая содержат изображение, 8 из них — QR. Языки: русский 28, казахский 19, смешанный 26, транслит 7. Есть прямое и скрытое продвижение, несколько переходов, противоречащие призывы, разные ветви, предупреждения, новости, обучение, бесплатные игры, обычные партнёрские программы и четыре намеренно недоступных положительных назначения.

Изображения включают поворот, JPEG-сжатие, мелкий шрифт, тёмный фон, международные пути и переносы URL. У четырёх материалов адрес присутствует только в QR; у четырёх видимый URL и QR различаются. Поэтому точный URL дополнительно измеряется на 28 изображениях с ожидаемым видимым адресом, QR — отдельно на восьми изображениях с кодом. Метрики всех 32 изображений сохраняются рядом, чтобы видеть неожиданные ложные извлечения.

`inputs.jsonl` содержит только нейтральные ID и материалы. В изображениях текстовые поля пусты; анализатор должен распознать пиксели. `pages.json` содержит контролируемые ответы транспорта. `annotations.jsonl` хранит truth, язык, контекст, исходный текст автора, ожидаемые URL/QR. `metadata.json` сохраняет время создания и хеш генератора. Метки не передаются worker: он сохраняет сырые предсказания до отдельного запуска агрегатора.

Идентификаторы и домены не обозначают класс. DEMO присутствует в обоих классах. Проверка нормализованного текста сопоставила новые входы с 314 различными прежними текстами: точных совпадений и кандидатов выше заданного порога не найдено. 102 новых домена не пересекаются с прежними. Это фильтр пересечений, а не доказательство семантической независимости. Общая тематика, автор и синтетические страницы остаются источниками смещения.

До первого предсказания исправлена ошибка эталона: пунктуация предложений попала в пять наборов ожидаемых URL. Изображения и входные тексты не менялись. Исходная разметка, метаданные и перечень исправлений сохранены в `reports/acceptance-v4/data-authoring-qa`. После `data-freeze.json` ни данные, ни ядро не изменяются.

## Три разные роли данных

| Роль | Где | Допустимое использование |
|---|---|---|
| Разработка OCR | datasets/ocr-dev-v4, отчёты ocr-dev-* | Выбор обработки и измерение стоимости |
| Регрессии | известные ошибки synthetic-v3, тесты context/branch/url_review | Проверка конкретных исправленных причин |
| Новый финальный тест | datasets/synthetic-v4 | Однократное сравнение заранее зафиксированных версий |

Synthetic-v4 после чтения результатов становится известным регрессионным набором. Следующая настройка требует нового dev и отдельного финального теста.

## Проверить сохранённый результат

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts\verify_version_v4.py
```

Команда проверяет SHA-256 ядра, протокола, оценщика, данных, исторических файлов и исходного архива v3, затем независимо пересчитывает confusion matrix из сырых предсказаний. Она не запускает модели и не проверяет истинность разметки.

## Повторить вычисление в новые файлы

Требуется установленное окружение, все модели v4 и извлечённая архивная v3. Архив v3 поставляется отдельно в `deliverables/releases/SafeTrace-KZ-v3-source.zip`; его хеш записан в `core-freeze.json`. Извлечь в новый `tmp/v4-baseline-source`, скопировать туда две первичные модели из `models/`. Старый исходный код не редактировать. На исходном рабочем компьютере эта папка уже подготовлена.

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_v4.py worker --version v3 --source tmp\v4-baseline-source --output reports\reproductions\v3-reproduction-01.json
.\.venv\Scripts\python.exe scripts\evaluate_v4.py worker --version v4 --output reports\reproductions\v4-reproduction-01.json
```

Выполнять последовательно, без параллельного OCR. Файлы не перезаписываются. Worker сверяет замороженные исходники/входы и использует отдельную базу. Сравнивать содержательные поля score/predicted/sufficient/materials; времена и новые IDs анализа могут отличаться. Официальный `aggregate` уже выполнен для сохранённых исходных worker-выходов и не должен повторно затирать их. Результаты повторов остаются отдельными.

Общая оценка — по случаям, а не по каждой публикации. Порог 65 и достаточность данных обязательны одновременно. Положительные отказы остаются FN. Query-метрика учитывает точные непустые последовательности параметров; пустой query не даёт искусственных успехов. Возможность найти правильный OCR-вариант не равна автоматическому извлечению.
