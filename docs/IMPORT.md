# Пакетный вход и транскрипции

Добавление через форму и обычный JSONL остаются доступны. Новый клиент преобразует один разрешённый экспорт чата Telegram в JSON или подготовленную SRT-транскрипцию. В первой операции данные остаются локальными.

```sh
python scripts/import_collection.py telegram chat.json --output batches.jsonl
python scripts/import_collection.py srt stream.srt --output transcript-batches.jsonl
```

`python` здесь — Python из окружения проекта. В Windows: `.venv\Scripts\python.exe`; в Linux/macOS: путь к вашему виртуальному окружению.

Чтобы также отправить пакеты **запущенному локальному** приложению:

```sh
python scripts/import_collection.py telegram chat.json --output batches.jsonl --submit
```

До 10 MiB на вход, до 1000 непустых сообщений/сегментов, до 20 материалов в каждом случае. Клиент ждёт завершения пакета перед следующим и обрабатывает заполненную очередь. Квитанция `batches.receipt.jsonl` содержит ID сразу после принятия и итоговый статус. После таймаута сначала проверьте этот случай, чтобы не создать дубликат. Выходные файлы не перезаписываются.

В Telegram сохраняются ID чата/сообщения, текстовые сущности, скрытое назначение текстовой ссылки и UTC-время из `date_unixtime`. Пустые сообщения и служебные события подсчитываются как пропуски. Вложения не скачиваются и не читаются автоматически. Имя канала остаётся заявленными данными экспорта.

В SRT каждая реплика сохраняет начальный и конечный таймкод в подписи источника и оригинальном тексте. В карточке и экспортируемой цитате можно увидеть, например, `[00:01:03,100 --> 00:01:05,900]`. Это импорт готовой транскрипции; распознавание речи и прямой эфир не реализованы.

Обычный JSONL для прежнего импорта содержит по одному материалу на строку:

```json
{"text":"Материал для проверки", "source":"Имя источника", "published_at":"2026-10-25T12:00:00+05:00"}
```

Файл `batches.jsonl` нового конвертера содержит целые пакеты, поэтому его не следует загружать в старую кнопку импорта материалов. Используйте `--submit` в команде конвертера.
