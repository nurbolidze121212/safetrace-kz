# SafeTrace KZ 2.3.0 — расширенный аудит и документация GitHub

22.10.2026. Ветка `codex/extended-link-audit`, исходная точка `69f5325`. Пользователь запросил расширение на подозрительные ссылки и сообщения, проверяемые объяснения, подробное научно ориентированное описание и инструкцию переноса сервера.

## Выполнено

- Добавлен `backend/link_audit.py`: пассивный разбор URL, границ домена, Unicode/punycode, адресов программ/скриптов, части перед @ и сочетания приза с запросом секрета. Не вызываются DNS, сеть или исполнение содержимого.
- Добавлен датированный справочник с одним примером Apple и официальным источником. Подтверждённые домены казино в него не выдумывались.
- API `GET /api/cases/{id}/link-audit`, отдельное скачивание JSON. Старые случаи не изменяются. Схема `link-audit-1.0`, вероятность `null`, состояние невыполненных проверок видно.
- Вкладка «Другие угрозы» и переход из режима показа; реальные ссылки на сохранённые основания. Мобильная ширина 390×844 проверена без горизонтального переполнения документа.
- Новый README, архив README v4, пять подробных документов: архитектура, расширенный анализ/API/источники, установка и перенос, исследовательское досье, GitHub-публикация. Обновлены ограничения, методика и дорожная карта.
- Скрипт создания/проверки исходного ZIP `scripts/package_source.py`: отслеживаемые рабочие файлы и проверенная сборка frontend, manifest размеров/SHA-256; без рабочей базы, ключей, моделей и окружений.
- Ночная автоматизация обновлена под новый запрос; расписание 00:00/02:00/04:00/06:00 Asia/Qyzylorda сохранено.

## Фактическая проверка

Полный backend: **330 passed за 53,75 с**. Одно предупреждение Paddle об отсутствии ccache, не ошибка. Frontend: **30 passed**, ESLint, TypeScript и production build прошли. Ruff прошёл. Preflight подтвердил приложение 2.3.0 offline, 94 версии Python-пакетов, 9 файлов моделей и 35 исходников/4 выхода frontend по fingerprint.

Браузер: создан авторский пример «Вы выиграли iPhone! Отправьте код из SMS: https://apple.com.claim.example/prize». Случай [1a1019fcd5d345e0b48eefeee9cb8f8d](http://127.0.0.1:8765/#case/1a1019fcd5d345e0b48eefeee9cb8f8d?view=security). Внешняя сеть выключена, основной маршрут явно неполный. Дополнительный аудит выявил два признака: встраивание `apple.com` в чужой узел и сочетание приза с запросом кода. Это не тест реальной мошеннической кампании.

В первом браузерном проходе найден дефект: доказательство открывало заявленное имя источника вместо текста. Исправлена связь с `content_evidence_ids`/`source_text`; добавлена регрессия. После исправления браузер открыл точный исходный текст. JSON реально скачан, ссылки на evidence проверены; `probability=null`, `network_requests=0`.

Скриншоты: [основания](link-audit-2.3/findings.png), [источник](link-audit-2.3/source.png), [мобильные основания](link-audit-2.3/mobile-findings.png). В финальном браузерном проходе ошибок/предупреждений консоли нет. Проверка физического телефона не заявляется.

До изменения сервера создан `data/backups/before-link-audit.zip`. Побайтно сохранены все 28 прежних случаев, 9 решений, 13 cache-записей и 10 оригиналов. Добавлен только авторский демонстрационный случай. Подробные текущие числа — в verification.json.

Среди 22 файлов прежнего core-freeze изменился только `backend/app.py` — API/версия оболочки. Правила, веса, OCR и pipeline не менялись. Новая финальная оценка классификатора не проводилась; старые метрики v4 не относятся к дополнительному аудиту. Проверять весь исторический freeze следует в исходниках v4, а не ожидать совпадения нового app.py.

## Что не выполнено

Нет подключённых актуальных репутационных баз, антивируса/песочницы, автоматической проверки владельца или лицензии, полного каталога брендов/казино, калиброванной вероятности, независимого пользовательского исследования и физического телефонного доступа. Явные статусы не имитируют эти возможности. Полный универсальный сканер не заявляется.

**GitHub не опубликован:** remote отсутствует, connector вернул пустой список доступных репозиториев, GitHub CLI отсутствовал в PATH; создание через браузер требует Sign in. Вход/создание аккаунта и доступ к репозиторию за пользователя не выдумывались. Документация и локальный комплект подготовлены; URL публикации не заявляется.

## Продолжение

Приоритет — расширить независимые проверки доказательств и новую dev-оценку; затем подключить выбранный репутационный источник с явным согласием и статусами свежести/ошибок. Увеличивать каталог брендов только по проверяемым источникам. Телефонное сопряжение проектировать отдельно от публикации исходников.
